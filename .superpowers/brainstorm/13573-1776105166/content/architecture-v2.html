What makes a judge agent "agentic" vs a plain API call?

Approach A: Plain API Call
  • One-shot: system prompt + tool call → approve/reject
  • No memory of past calls
  • No tools — can only reason about what's in the prompt
  • Stateless — every call is independent
  • Fast, cheap, simple
Approach B: Agentic Judge
  • Memory: sees history of all past tool calls this session
  • Tools: can look up known vulns, check package names, inspect patterns
  • Context accumulation: "3rd suspicious call → escalate"
  • Reasoning chain: multi-step analysis before voting
  • Slower, costlier, but smarter

Judge Agent Capabilities (per agent)

Capability Param Validator Intent Aligner Threat Modeler
System prompt Structural safety of args Action-task alignment Adversarial exploitability
Session memory Rolling window of last N tool calls + their verdicts
Tools available check_path_traversal, check_injection_pattern get_task_description, check_scope lookup_known_vuln, check_typosquat
Output {decision, confidence, reason, tools_used}

The key difference: agentic judges have memory across calls and tools to investigate with — they don't just read the prompt and guess.

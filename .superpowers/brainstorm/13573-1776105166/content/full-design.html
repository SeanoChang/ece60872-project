Design Section 3: Complete System Design Summary

Everything we've agreed on — review before I write the spec

1. What We're Building

A multi-judge voting system that replaces human approval in Claude Code. Instead of a human clicking "approve" or using --dangerously-skip-permissions, an agentic cluster of LLM judges independently evaluates each tool call and votes approve/reject. This enables fully autonomous coding agent operation without sacrificing safety.

2. Architecture

Claude Code (Agent)

Real Claude Code CLI inside Docker. Gets a task, operates autonomously. PreToolUse hook intercepts every Bash/Edit/Write call.

Judge Cluster (FastAPI :8080)

Persistent agentic server. Each judge has: system prompt, session memory (past tool calls), tools (file inspection, vuln lookup, typosquat check). Dispatches judges in parallel, majority vote.

Honeypot (:9999)

Ground truth sensor. Logs all HTTP requests. Canary key match → attack succeeded. Real key match → tripwire halt. Always returns 200.

Docker Container

Per-scenario workspace. Planted canary keys. Network: api.anthropic.com + localhost only. Destroyed after each run.

3. Hook Integration

// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash|Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "python judge_hook.py",  // thin client → POST to :8080
        "timeout": 30
      }]
    }]
  }
}
Hook reads tool call from stdin → POSTs to Judge Cluster → returns exit 0 (approve) or exit 2 (reject + reason)

4. Two Testing Tiers

Tier 1: Synthetic Benchmarks
GitHub Actions (automated)
  • MCPSecBench — MCP tool poisoning scenarios
  • InjecAgent — indirect prompt injection, L0-L4 enhancement ladder
  • 30-50 scenarios × 6 ablations × 3 reps
  • Stateless (A) vs Agentic (B) judge comparison
  • Purpose: statistical power, systematic coverage
Tier 2: Real-World Case Studies
Cloud VM (realistic)
  • Axios attack (March 2026) — npm supply chain, postinstall RAT
  • CVE-2025-68143 — Anthropic Git MCP server injection
  • LiteLLM PyPI compromise (March 2026) — malicious package
  • Full end-to-end, real packages, real agent behavior
  • Purpose: ecological validity, live demo

6. Metrics & Comparisons

Primary Metrics
  • Detection rate (judges block before exfil)
  • False positive rate (judges block benign calls)
  • Condorcet gap (predicted vs observed voting accuracy)
  • Quorum survival rate (Byzantine tolerance)
Comparison Axes
  • 1 judge vs 3 judges (does voting help?)
  • Stateless (A) vs Agentic (B) judges
  • Honest vs Byzantine (does voting survive?)
  • Our system vs Claude Auto Mode (17% FN)
  • Our system vs AEGIS (1.2% FPR)

8. Novel Contributions (for the paper)

  1. First implementation of multi-judge voting for tool-call safety in a real coding agent
  2. First integration of automated judge approval via hooks replacing human oversight
  3. Comparison of stateless vs agentic judges — does memory/tools improve detection?
  4. Empirical measurement of Condorcet gap for safety voting (common-mode failure)
  5. First Byzantine tolerance test for LLM judge voting on tool calls
  6. Validated against real-world attacks (axios 2026, CVE-2025-68143)
